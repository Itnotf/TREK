## 对 Trek 的建议（研究推论）

成都例提示“日内活动与服务衔接”，自驾例提示“路线与沿途生活安排”，TripIt 提示“计划与预订凭证分层”。以下是面向 Trek 的取舍，不是来源共同规定的行业标准。

| 信息 | 优先级与最小内容 |
| --- | --- |
| 全程概览 | 必需：日期或天数、起终点、路线串联、主题与节奏、预算范围或待定。 |
| 逐日路线 | 必需：当天起终点、按顺序的地点、当天重点及过夜地；抵达、离开日也要安排。 |
| 时间与活动 | 必需：上午/下午等时间段、停留时长、具体做什么；固定预约才锁定时刻，其余标建议。 |
| 交通段 | 必需：每段从哪里到哪里、方式、估时与缓冲；估时标来源，未知则待确认，不伪造精确数值。 |
| 用餐与休息 | 必需：留出时间和所在区域；具体餐厅、菜品为辅助，可注明自理。 |
| 住宿 | 过夜行程必需：每晚推荐区域/类型及理由。实际预订另列酒店、入住退房、状态与凭证；只有确认信息才能标“已订”。 |
| 费用与预约 | 条件必需：付费项目注明估算/待确认、币种、按人或按组及包含范围；预约事项注明入口、时段与状态。预算不等于已支付。 |
| 图片与备选 | 图片、背景故事、更多餐馆为辅助；关键活动受阻时，应有替换活动或休息方案，并说明触发条件。 |

**建议验收方式：** 用户应能直接读出“何时在哪里做什么、怎样到下一站、何处吃住、哪些还待确认”。仅有景点和每日长备注无法直接呈现这些关系。优先生成“全程概览＋逐日有序事件＋交通连接＋待办”，备注只补充理由和提醒；缺失事实显式留待确认。

## 补充：完整攻略与 Trek 栏目含义（2026-10-30）

用户反馈：当前产物像流水账，整体不像完整旅游攻略。此次直接阅读以下成品，补充内容组织参考；不将页面中的价格、交通耗时或营业信息视为已核实的实时事实。

### 成品页面事实

- **[Trip.com：成都重庆五天四夜攻略](https://go.trip.com/zh-my/china/ctu-ckg.html)**：包含全程安排及逐日景点、餐饮、住宿候选、交通连接。景点说明具体体验与建议停留，酒店附图片、地址和详情入口。换城日把高铁抵达、寄存行李、解放碑和洪崖洞、用餐及回酒店串联起来。该页属于 Trip.com，价格以马来西亚市场币种展示，适合参考信息结构。
- **[携程用户游记：成都三天两夜攻略](https://you.ctrip.com/travels/chengdu104/4029505.html)**：分别交代往返及市内交通、住宿区域选择、三天路线、景点门票、美食和注意事项。发表于 2021-08-26，包含具体酒店推荐，属于用户游记；旧价格与推荐不能直接作为当前出行依据。

### 产品取舍（研究推论，尚未实施）

攻略应同时回答“怎么安排”和“为什么值得这样玩”。在全程概览下，每天先讲主题、重点体验和路线理由，再提供活动顺序、地点介绍、吃住选择及交通衔接。午餐不能长期只有“午餐 60 分钟”，住宿也不能长期只有“某区域待选”；应提供有依据的区域、菜品或酒店候选及选择理由，并区分推荐与已预订。

保留日程编辑能力，但默认阅读应呈现完整攻略。普通活动按上午、下午、晚上与建议时长组织，固定车次和预约才强调准确时间。休息应结合真实可用的场所与旅行体验，不能靠大量等待条目填满一天。图片帮助认识地点；不能替代介绍、选择理由和可靠信息。

### Trek 栏目事实与命名建议

依据 [Trip Planner Overview](Trip-Planner-Overview.md#tabs)、[Tours](Tours.md) 及当前页面实现：

- **计划（Plan）**组织每天的地点、活动、交通、住宿及其他安排，是整趟旅行的日程。
- **游览（Tours）**是活动路线工具，可绘制路线或导入 GPX/KML 等轨迹，用于徒步、骑行、城市漫步等活动；路线可以再加入某一天的计划。

例如，一条徒步路线属于 Tours，而“第二天上午走这条路线，之后午餐并回酒店”属于 Plan。Tours 并不是完整攻略的另一个名称。当前 AI 改造主要生成 Plan 中的地点、活动和日程，没有自动创建 Tours 轨迹。

建议将“计划”改称“每日行程”，“游览”改称“活动路线”，并以攻略总览串联景点、吃住、交通与每日行程。以上仅记录方向，不代表已经修改导航或实现攻略页面。
