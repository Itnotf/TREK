## 对 Trek 的建议（研究推论）

成都例提示“日内活动与服务衔接”，自驾例提示“路线与沿途生活安排”，TripIt 提示“计划与预订凭证分层”。以下是面向 Trek 的取舍，不是来源共同规定的行业标准。

| 信息 | 优先级与最小内容 |
| --- | --- |
| 全程概览 | 必需：日期或天数、起终点、路线串联、主题与节奏、预算范围或待定。 |
| 逐日路线 | 必需：当天起终点、按顺序的地点、当天重点及过夜地；抵达、离开日也要安排。 |
| 时间与活动 | 必需：上午/下午等时间段、停留时长、具体做什么；固定预约才锁定时刻，其余标建议。 |
| 交通段 | 必需：每段从哪里到哪里、方式、估时与缓冲；估时标来源，未知则待确认，不伪造精确数值。 |
| 用餐与休息 | 必需：留出时间和所在区域；具体餐厅、菜品为辅助，可注明自理。 |
| 住宿 | 过夜行程必需：每晚推荐区域/类型及理由。实际预订另列酒店、入住退房、状态与凭证；只有确认信息才能标“已订”。 |
| 费用与预约 | 条件必需：付费项目注明估算/待确认、币种、按人或按组及包含范围；预约事项注明入口、时段与状态。预算不等于已支付。 |
| 图片与备选 | 图片、背景故事、更多餐馆为辅助；关键活动受阻时，应有替换活动或休息方案，并说明触发条件。 |

**建议验收方式：** 用户应能直接读出“何时在哪里做什么、怎样到下一站、何处吃住、哪些还待确认”。仅有景点和每日长备注无法直接呈现这些关系。优先生成“全程概览＋逐日有序事件＋交通连接＋待办”，备注只补充理由和提醒；缺失事实显式留待确认。
